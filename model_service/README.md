# 手环跌倒识别：第一版随机森林模型

已用 UMAFall 公开数据实际完成训练。本版本输入一段完整的 10–20 秒手腕运动记录，输出“疑似跌倒 / 非跌倒”和模型分数，可在电脑或云端演示。它还不能直接承担连续监测、实时报警或真实老人跌倒识别。

**已提供可运行的中文演示页面和 FastAPI 推理服务。** 选择公开样例即可展示曲线回放、识别及模拟确认流程，无需自行采集数据。启动与云端部署见 [演示应用使用说明](DEPLOY.md)。下文介绍模型训练本身。

## 随机森林是什么

一棵决策树会连续提出问题，例如“冲击是否明显”“随后是否静止”，沿着不同分支给出判断。随机森林训练许多这样的树，每棵树随机抽取训练记录，并在分叉时从随机挑选的特征中选择判断条件，最后汇总各棵树的预测。

这里使用 400 棵树。树的分叉条件由带标签的数据学习得到；人工负责设计输入特征和训练流程。因此，它是机器学习模型，不要求使用神经网络或大模型。输出分数未经概率校准，不能解释成医学上的跌倒概率。

## 已实现的 pipeline

1. 下载指定的 UMAFall 修正版 ZIP，并检查 MD5；自动下载的数据存放于系统临时目录，使用后清理。
2. 按每个文件的传感器映射表提取 **WRIST 的三轴加速度和三轴陀螺仪**。不混入腰部、胸部或手机数据。
3. 从原始文件名读取参与者、动作和跌倒标签。这些信息用于分组、监督学习与错误分析，不作为模型特征。
4. 排序时间戳、合并重复采样、检查缺失和间断，对齐两路传感器并重采样到 20 Hz；高采样率输入先低通再降采样。
5. 提取 45 个特征：加速度/角速度模长统计量、加速度变化率、强冲击比例、静止比例与最长静止时间、峰值前后运动量、安静起止段的朝向变化等。
6. 按参与者划分训练和测试。外层 5 折评估泛化能力；每个外层开发集内部再做 4 折分组验证，选择偏重召回率的 F2 最优阈值。缺失特征的中位数填补仅在对应训练集拟合。
7. 与单一“加速度峰值超过阈值”规则比较；把模型、特征顺序、单位、判别阈值及完整评估报告一起保存到 `model.joblib`。

“姿态”在这里仅指安静时手腕相对重力方向的变化线索，不能据此直接断定全身躺倒。冲击、姿态、静止都是输入证据，最终组合关系由树学习，并非写死的“满足三项就跌倒”。

## 本次实测结果

训练日期：2026-10-19。原始 746 条记录，经质量检查保留 **737 条、19 名参与者**，其中跌倒 201 条、非跌倒 536 条。排除 9 条：7 条存在超过 0.75 秒的采样间断，2 条有效采样率低于 14 Hz。

以下为外层 5 折的测试预测汇总；每条记录的预测来自未用该参与者训练的模型。参数固定，阈值只在对应开发集确定。

| 指标 | 随机森林 | 单一加速度阈值 |
|---|---:|---:|
| 跌倒召回率：跌倒中识别出的比例 | 93.03% | 96.52% |
| 精确率：判为跌倒的记录中真正跌倒的比例 | 83.86% | 50.65% |
| 非跌倒记录误报率 | 6.72% | 35.26% |
| F1 | 0.882 | 0.664 |
| 识别出的跌倒 / 全部跌倒 | 187 / 201 | 194 / 201 |
| 误报 / 全部非跌倒 | 36 / 536 | 189 / 536 |
| 漏检跌倒数 | 14 | 7 |

随机森林减少误报，但漏检有所增加，不能宣称所有指标都更好。不同外层折的随机森林召回率为 81.25%–100%，说明结果受参与者差异影响。较多误报来自举手、拍手和上床躺下。

这只是同一个公开数据集上的模拟动作评估，不能当作真实老人日常佩戴效果；“非跌倒记录误报率”也不是每小时误报次数。该规则对照只使用加速度峰值，并不代表所有多阶段规则算法。

交付的 `model.joblib` 保存外层第 0 折的模型：用 18 名参与者的 550 条记录训练，留出参与者 18 的 187 条记录，阈值约 0.20096。它在这一单独留出集识别出 54/55 次跌倒，误报 14/132 条非跌倒记录。上表是五个模型的交叉验证汇总，不是此单一文件在全部数据上的独立测试成绩。

本机完成数据处理、全部嵌套验证和保存约 **29 秒**，不含下载与安装；模型文件约 **440 KiB**。此大小是压缩后的电脑端文件大小，不代表单片机 RAM 或部署成本。

## 安装与运行

在项目根目录运行以下命令。建议使用独立 Python 环境；本次实测 Python 3.13.11，依赖版本已固定在 `requirements.txt`。训练使用 CPU，不需要 GPU。

```bash
python -m pip install -r model_service/requirements.txt

# 查看已训练模型的内嵌评估报告，不生成报告文件
python -B model_service/pipeline.py inspect

# 自动下载、训练、验证，更新 model.joblib
python -B model_service/pipeline.py train

# 或使用已下载的指定修正版数据
python -B model_service/pipeline.py train --data-zip /path/to/UMAFall_Dataset_corrected_version.zip

# 对自己采集的完整记录推理
python -B model_service/pipeline.py predict --csv /path/to/wrist_trial.csv

# 运行自动化测试，不生成工作目录缓存
python -B -m pytest -q -p no:cacheprovider model_service/test_pipeline.py
```

`train` 可用 `--output /path/to/model.joblib` 指定最终模型路径，`predict` 和 `inspect` 可用 `--model` 指定模型。默认随机种子为 42。训练报告只打印到终端并嵌入模型，不额外生成日志、图表或数据副本。只加载可信来源的 joblib 文件。

## 自采 CSV 格式

表头必须严格使用以下顺序，每行是一组同步采样值：

```csv
timestamp_s,ax_g,ay_g,az_g,gx_dps,gy_dps,gz_dps
0.00,0.01,0.02,1.00,0.2,0.1,0.3
0.05,0.02,0.01,1.01,0.1,0.2,0.1
```

这里只展示格式，实际输入应包含 **10–20 秒完整动作，建议约 15 秒**，并保留动作前后的上下文。当前模型使用整段统计量和事后样本，不适用于直接切成 1–2 秒窗口或宣称即时发现跌倒。

- `timestamp_s`：秒，使用传感器实际采样时间，不能用蓝牙包抵达手机的时间代替。
- `ax_g, ay_g, az_g`：加速度单位 g，**保留重力**；静止时三轴模长应约为 1。若驱动输出 m/s²，先除以 9.80665。
- `gx_dps, gy_dps, gz_dps`：角速度单位 °/s；若驱动输出 rad/s，先乘以 180/π。
- 两路传感器使用一致的设备轴定义。建议以稳定的 20 Hz 或 50 Hz 导出；不能用全零伪造缺失的陀螺仪。
- 模型文件中的标签：`suspected_fall` 为疑似跌倒，`non_fall` 为非跌倒。CSV 不包含真值标签；自采数据的参与者编号、动作标签、设备和佩戴信息需另行记录，评估时关联。

公开数据与自制手环可能在采样率、量程、佩戴松紧和动作分布上不同。接入自己的板子后，应先检查单位、采样丢失和量程饱和，再评估模型。

## 当前协作范围

当前使用公开数据进行课程演示，模型放在服务端，不要求先自采数据，也不部署到手环。仓库根目录的 `app/` 留给 App 同事，推理接口约定见 [API 文档](../docs/API.md)。

已交付训练流程、原版 45 特征随机森林、四条公开样例和 FastAPI 演示服务。启动服务不需要重新训练或下载完整数据集。当前样例和模型绑定，后续实验候选不会自动替换演示模型。

App 可先用公开样例对接上传、结果展示、状态查询和确认操作；接入手环后，再检查采样时间、单位、通道顺序和数据质量。训练与评估代码没有实现蓝牙固件或手机端。

下一版若要连续监测，需要补充连续记录中的事件起止时间标注、滑动窗口标签、仅使用当前及过去样本的处理方式及报警去重，再测每小时误报次数及事件发现延迟。训练脚本没有实现这些内容，也没有包含蓝牙固件和手机端。新增的 Web 应用已提供推理 API 和模拟用户确认流程，见 [应用说明](DEPLOY.md)。

当前建议先让手环采样，电脑或云端运行 sklearn 模型。若后续要求在 nRF52840 上直接推理，需要单独做模型简化、嵌入式导出，以及 Flash、RAM 和耗时测量；不能把 `.joblib` 直接烧到板子。
