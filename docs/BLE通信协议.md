# 手环 ↔ 手机 App BLE 通信协议 v0.1

手环主控为 **XIAO nRF52840 Sense Plus**（板载 LSM6DS3TR-C 六轴 IMU），通过 BLE 把数据发给老人随身手机上的 Flutter App，App 再经 HTTP 中转到云端。

## 1. BLE 服务与特征（Nordic UART Service，NUS）

nRF52840 生态的事实标准，调试工具（nRF Connect、LightBlue）都直接支持。

| 项目 | UUID | 方向 | 说明 |
|---|---|---|---|
| Service | `6E400001-B5A3-F393-E0A9-E50E24DCCA9E` | — | NUS 服务 |
| TX 特征 | `6E400003-B5A3-F393-E0A9-E50E24DCCA9E` | 手环 → 手机 | Notify |
| RX 特征 | `6E400002-B5A3-F393-E0A9-E50E24DCCA9E` | 手机 → 手环 | Write（无响应即可） |

- 广播名：**`YianBand`**（App 按名字过滤扫描结果）
- App 连接后请求 **MTU ≥ 131**（Android 调 `requestMtu`）。
- 数据格式：**UTF-8 JSON，每帧以 `\n` 结尾**。一帧可能被拆到多个 Notify 包里，App 端按字节流累积、遇 `\n` 切帧（`band_protocol.dart` 已实现），固件端按 20 字节分片发送；背压超过 250ms 或断连时中止当前帧，尚无事件送达回执保证。

## 2. 帧定义

### 2.1 手环 → 手机

**六轴原始帧 `raw`**（每 50ms 一帧 @20Hz，跌倒识别的模型输入，对齐 docs/API.md §3）

```json
{"t":"raw","s":[10.123,0.0102,0.0231,1.0032,1.234,-2.345,0.456]}
```

`"s"` 数组固定 7 个元素，列序与 model_service 推理输入一致：

| 序号 | 字段 | 单位 | 说明 |
|---|---|---|---|
| 0 | `timestamp_s` | 秒 | 同一记录内时间戳，自开机起累计 |
| 1–3 | `ax_g, ay_g, az_g` | g | 三轴加速度，保留重力 |
| 4–6 | `gx_dps, gy_dps, gz_dps` | °/s | 三轴角速度 |

App 将 raw 帧缓冲成 10–20 秒窗口（自动滚动保留最近约 19 秒），用户点「运行跌倒识别」
或疑似跌倒触发时调用 `POST /api/predict`。采样率必须 ≥14Hz，**不得用全零数组代替陀螺仪**。

**状态帧 `st`**（每 2 秒一帧，实时页展示）

```json
{"t":"st","g":1.02,"p":3.2,"r":-4.0,"s":0,"b":87,"q":123}
```

| 字段 | 含义 | 单位/取值 |
|---|---|---|
| `g`  | 合加速度模（√(ax²+ay²+az²)） | g |
| `p`  | 俯仰角 pitch | 度 |
| `r`  | 横滚角 roll | 度 |
| `s`  | 是否持续静止（端侧判断） | 0/1 |
| `b`  | 电量 | 0–100 |
| `q`  | 帧序号 | 递增整数 |

**事件帧 `ev`**（端侧初筛触发时立即发送）

```json
{"t":"ev","k":"fall","i":3.2,"w":12.0,"c":0.88,"q":124}
```

| 字段 | 含义 |
|---|---|
| `k` | 事件类型：`fall` 疑似跌倒 / `sos` 短按 SOS（或手机端 SOS）/ `lowbat` 低电量 / `cancel` 取消告警 |
| `i` | 冲击峰值 g（fall 时有效） |
| `w` | 冲击后静止秒数（fall 时有效） |
| `c` | 端侧初筛选信度 0–1 |
| `q` | 帧序号 |

**确认帧 `ok`**：`{"t":"ok","q":123}` —— 手机确认收到事件帧（可选）。

### 2.2 手机 → 手环

| 帧 | 含义 |
|---|---|
| `{"t":"sos-on"}` | 手机端 SOS 触发 → 手环播放 1.2s 声音/振动/红灯提示 |
| `{"t":"sos-off"}` | SOS 取消 → 手环清除告警并停止本地提示（不回发 cancel，避免回环） |
| `{"t":"mute"}` | 静音当前语音/震动提示 |
| `{"t":"ok","q":n}` | 事件帧回执 |
| `{"t":"ask"}` | 请手环播放/触发“您还好吗”语音询问（原型阶段由手机 TTS 播放，此帧预留） |

## 3. SOS / 取消 / 跌倒联调流程

- 老人操作手表，监护人使用 App。SOS 按键 D6–GND：**短按**（按下后松开，未走成长按取消）发送一次 `ev{sos}` 并进入告警；**长按**（≥1.5s）发送 `ev{cancel}` 取消告警；D7 取消键等效于长按。
- SOS 本地反馈：约 977Hz I²S 正弦提示音、马达和板载红灯同步亮/响/振 0.2s、停 0.2s，总计 1.2s。提示结束不撤销 SOS；屏幕保持告警状态直到取消。跌倒提示持续 10s，USB 模块测试持续 2s。
- App 收到 SOS 立即显示"老人紧急求助"并语音/触觉提醒，同时调用 `POST /api/events/sos` 同步立即告警事件。
- 手表长按 / D7 发送 `ev{cancel}`，App 显示“老人已取消”；手机端长按直接更新 App 并下发 `sos-off`。两条路径都通过 `POST /api/events/{id}/cancel` 保存取消状态并保留原告警记录；取消不等于已核实安全。
- 创建在途时到达取消，先更新监护人界面，再补交取消；迟到的求助响应不能覆盖取消。
- 监护人点击"我已知晓"仅关闭提醒，之后老人按取消仍可更新原事件。
- 云端失败不阻止本机告警；显示未同步状态，可在事件记录中重试。队列仅在本次 App 进程内存中保存。
- 新的 SOS 帧立即创建新告警，不因上一条云端未同步而被合并；"重试同步"仅重试所选事件。
- App 在重新连接时清除上一连接的半帧；若一行中含发送中断留下的残片，可恢复其后以 `{"t":` 开头的完整尾帧。
- 重复帧按类型和 q 去重（连接内最近 128 帧）；短按后需松手才能再次触发。
- 两键同时按下时取消优先，同一次 D6 按压被 D7 取消后松手不会再触发。松开即触发：只要没有走成长按取消，任何时长的松开都发送求助，不留 1–1.5s 空档（旧版此处会静默丢弃，已修正）。断连时停止本地声音/振动，D6 长按和 D7 仍可清除本地告警；离线短按不发送 SOS，不提供离线补发。
- fall 仍使用 10–20 秒六轴记录和服务端跌倒识别契约；SOS 不受推理任务阻塞。
- 手表显示"SOS已触发"仅表示按键已触发，不代表远程监护人已收到。
- 手环到 App 需手机在蓝牙范围内且 App 在前台；服务端可选配置企业微信群通知，App 尚无后台常驻保证。服务端不发送短信或电话。
- BLE UART 分片发送有 250ms 背压上限，协议没有 ACK/离线重发，实机需验证消息到达情况。

## 4. 固件参考示例

见 `firmware/yianband_example/yianband_example.ino`（Arduino + Seeed nRF52 板包），
包含：NUS 服务搭建、IMU 采集打包、简单跌倒初筛规则、SOS/取消按键。烧录前需：

1. Arduino IDE 安装 Seeed nRF52 Boards 板包（见 Seeed Wiki "XIAO BLE" 教程）
2. 库管理器安装 `Seeed Arduino LSM6DS3`
3. `#define DEVICE_NAME "YianBand"` 可改成每位老人独立名字（如 `YianBand-01`）

### 当前固件接线与测试

- HR8833：IA1 → D1、IA2 → D2，马达 → MA1/MA2；VCC、VM → 3V3，IB1/IB2 → GND。
- MAX98357A：BCLK → D8、LRC → D9、DIN → D10、SD → D3；VIN → 3V3，GAIN 悬空。扬声器接 SPK+/SPK−，不接 GND。全部模块共地。
- 屏幕 SDA → D4、SCL → D5；SOS → D6/GND，取消 → D7/GND。
- USB 串口 115200：`a` 测声音、`v` 测马达、`t` 同时测试（各 2s），`x` 停止；测试不产生 SOS 事件。
- 下行 JSON 以换行结束，固件支持分片与连续多帧，连接切换时清除半帧；`mute` 只停止本地提示，不撤销 SOS。
